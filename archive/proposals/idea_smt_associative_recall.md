# Идея развития: преодолеть неспособность SMT к associative recall с помощью MemUP-подобной цели «только по памяти»

*Черновик для обсуждения с научником, 17.10.2026. Не протокол: перед экспериментами нужна отдельная предрегистрация.
Опирается на результаты 16–17.10 (`status.md`, `outputs_mqar/`, `proposals/paper_alignment.md`).*

## 1. Проблема
* SMT (Kumar & Isola, arXiv 2606.06479) учит нелинейные RNN без BPTT: энкодер-teacher строит predictive state m_t,
  updater учится одному шагу, затем DMT. Метод сильнее BPTT на state tracking, копировании и пикселях, но сами авторы
  отмечают провал на **associative recall** (Keys-Values, рис. 3).
* Для современных RNN это центральный навык: Zoology показывает, что разрыв по качеству между attention и эффективными
  моделями в основном объясняется именно ассоциативным вспоминанием.
* Если SMT не умеет этому учить, метод неприменим там, где RNN нужнее всего.

## 2. Что уже установлено у нас
MQAR pilot01: словарь 128, T = 64, 8 пар, без шума.

**Диагноз (гипотеза).** Loss декодера на новых данных падает до ~1,46 (ниже ln 8 ≈ 2,08): teacher учится тому, что
можно вывести из промежуточных входов декодера x_{t+1..k}. Это пары, записанные после anchor, и набор значений.
Стимула хранить связки в m_t почти нет: предсказательная цель SMT даёт декодеру **обходной путь**. На Stack мы видели
то же явление в мягкой форме: 59% «неожиданных» целей не требовали памяти.

## 3. Гипотеза
**H.** Вспомогательная цель «ответ только по памяти» — предиктор MemUP q(y_k | m_t, x_k), который видит память
и **локальный** контекст цели (в MQAR это ключ-запрос), но не промежуточные входы:
* устраняет обходной путь;
* даёт O(1)-путь кредита от запроса к записи;
* позволяет SMT учить RNN associative recall без BPTT.

Отбор целей по неожиданности (MemUP) делает цель дешёвой (K целей на anchor) и фокусирует её на ответах, которым
нужна память.

Почему именно P1 здесь (в отличие от Stack): в MQAR ответ однозначно определяется парой (память, ключ), локальный
контекст информационно достаточен. Это ровно режим, для которого MemUP и создавался.

## 4. Метод (эскиз)
L = L_SMT + β·L_mem,

L_mem = Σ_t Σ_{k ∈ S_t} CE(y_k, q_φ(m_t, x_{k−r+1..k})).

* q_φ — небольшой «запросный» декодер. Варианты: та же архитектура, что декодер SMT, но без промежуточных входов;
  или cross-attention запроса к memory-токенам.
* S_t — K целей из будущего (k > t), выбранных по неожиданности детектора. Варианты: локальное окно; собственная
  ошибка q_φ, как в supervised-экспериментах MemUP; мягкое сэмплирование τ = 0,02, как в статье.
* Градиент L_mem идёт в энкодер teacher (что хранить). RNN учится через L_dyn и DMT, без изменений.
* **Абляции:**
  * oracle-отбор — цели, чей ключ записан до t;
  * random-K;
  * без отбора — все цели;
  * β;
  * K;
  * r;
  * маскирование обходного пути у исходного декодера вместо добавки.

## 5. План экспериментов (по нарастанию стоимости; каждый следующий — только если предыдущий дал сигнал)
1. **Oracle-пилот** (~1 ч кода, ~0,5 ч GPU): pilot01, L_mem с oracle-целями. Учит ли teacher связывание?
   * Нет — идея в этой форме не работает, разбираемся (запросный декодер, β, curriculum по числу пар).
   * Да — дальше.
2. **Честный отбор:** surprise / random / все цели при одинаковом K; итоговая RNN после DMT; удержание (H2).
3. **Масштаб, как в Zoology:**
   * число пар 4…64, длина 64…512, ширина 64…256;
   * сравнение: Transformer, RNN + BPTT/TBPTT, исходный SMT, SMT + L_mem;
   * плюс линейные RNN / Mamba / Based из кода Zoology как внешние ориентиры;
   * метрика: точность по всему словарю, как в Zoology.
4. **Неухудшение и общность:** Stack (у нас уже есть база v4) и MNIST-пиксели (согласовано с научником на потом).
5. **Шум:** MQAR с шумовыми токенами — проверка Noisy-TV (обсуждалась с научником 11.10). Учитывать полезность памяти,
   а не только неожиданность.

## 6. Метрики и честность
* Предрегистрация на каждый этап: test один раз, 3+ seeds только для итоговых утверждений.
* Стоимость (шаги, последовательности, время, память) — как в v4.
* Отдельно сообщать: teacher, итоговую RNN, probe памяти, H2. Улучшение teacher или probe не выдавать за улучшение RNN.

## 7. Риски
* **Слабая постановка.** Teacher может не выучить связывание и с L_mem: обходной путь не единственная причина,
  возможна трудность «распределения пар по слотам» в memory-токенах. План Б — архитектура updater с матричной
  памятью (fast weights / DeltaNet-подобная). SMT допускает произвольный updater.
* **Новизна.** Проверить работы после SMT (2026):
  * NextLat (Teoh et al.);
  * обучение RNN на MQAR без BPTT;
  * auxiliary losses для памяти (Venkatraman et al., predictive-state RNN);
  * работы группы MemUP.
* **Масштаб для A\*.** Одного MQAR мало: нужны масштабирование, сильные бейзлайны и одна естественная задача.
