# Настоящие примеры: позиции, токены, метки, маски, окна

* **Генерация:** все таблицы созданы командой `python checks/make_examples_ru.py` из настоящих генераторов —
  последовательность 0 validation-потока (501 — Stack, 511 — MQAR).
* **Короткий вывод в терминал:** `python smt_minimal.py trace --task stack|mqar`.
* **Столбцы:**
  * «токен» — целое число из генератора;
  * «вход» модели — тот же токен на той же позиции, сдвига нет ни в одной задаче;
  * «метка» — правильный ответ на этой позиции, −1 = ответа нет;
  * «маска лосса» = `target_mask` = метка ≠ −1;
  * «источник» — позиция, где был записан ответ (push элемента или значение пары);
  * delay = t − источник.

### Что здесь видно
* Ответ на pop стоит на позиции самого pop (`x_t = 0`, `y_t` = снятый элемент). RNN после обновления входом `x_t = 0`
  читает `y_t` из `m_t` (`smt_minimal.py:496-498`).
* Один и тот же ответ `y_30 = 1` входит в SMT-loss многими парами (якорь a, выход j = 30 − a):
  * при **Tf = 8** (целевая постановка) — только якоря a = 23..30, это ближний `L_dec^Tf`; пары с a ≤ 22 — дальние
    (j ≥ 8); в `base_window` они не обучаются, в `ctx_far` попадают в отбор `L_far`;
  * при **Tf = T = 64** (Stack v1, абляция `tf64`) — все якоря a = 0..30.
* Якорь a = 19 ≥ источника 19: элемент уже в памяти m_19 (пара `prefix`). Якорь a = 18 < 19: элемент будет записан
  внутри входов декодера x_19 = 1 (пара `future`), его можно «списать» из входов декодера без памяти.

## MQAR: два разных режима чтения памяти teacher (вопрос Айдара)

На примере T = 16, N = 2, запрос `t = 8` (ключ 5, ответ 121, пара записана на позициях 2–3):

| режим | память | что видел энкодер | что видит декодер | выход | где в коде |
|---|---|---|---|---|---|
| **j = 0 на позиции запроса** (так оценивались все архивные опыты) | m_8 | x_0..x_8 = `16 97 5 121 16 0 0 0 5`: все пары **и сам ключ запроса** | ничего, кроме памяти | j = 0 → y_8 | `smt_minimal.py:507-515`; архив: `smt_memup_mqar.py:465-476`, `checks/mqar_bottleneck_test.py:57` |
| **память до запроса, сразу после пар** (`teacher_pre`, `after_pairs`) | m_3 | x_0..x_3 = `16 97 5 121`: все пары, запроса нет | x_4..x_8 = `16 0 0 0 5`: предыдущий запрос и **ключ запроса** | j = 5 → y_8 | `smt_minimal.py:503-506, 515` (новое) |
| **память за шаг до запроса** (`teacher_pre`, `before_query`) | m_7 | x_0..x_7: все пары и предыдущий запрос | x_8 = `5`: только ключ запроса | j = 1 → y_8 | там же (новое) |

### Проверено по индексам и маскам (`checks/test_minimal_equivalence.py::test_mqar_visibility_and_no_leak`)
Проверка на 256 последовательностях для T = 16, N = 2 и T = 32, N = 4.
* Все запросы стоят после всех пар (t ≥ 2N).
* После пар во входе нет ни одного токена-значения (≥ V/2): **ответ нигде не утекает** ни в энкодер, ни в декодер.
* Для якоря a ∈ {2N−1, t−1}:
  * окно энкодера ровно x_0..x_a и содержит все пары;
  * входы декодера выхода j = t−a ровно x_{a+1..t}, последний из них — ключ запроса;
  * метка `y_fut[a, j]` = y_t.
* Для j = 0 окно энкодера — x_0..x_t, его последний токен — ключ запроса.

### Что из этого следует для SMT на коротком MQAR
* **По индексам задача teacher-у доступна в обоих режимах:** при Tf = T все пары (a, t) с 2N−1 ≤ a ≤ t входят в
  L_dec. Ключи и значения есть в окне энкодера, ключ запроса есть либо в окне энкодера (j = 0), либо во входах
  декодера (j > 0).
* **Архивные числа teacher** (свип по длине: 50,8% / 49,3% / 24,8% среди записанных; тест узкого места: 48% / 12,8%)
  измеряют **только j = 0**. Режим «память до запроса» не измерялся, хотя на нём teacher тоже обучался.
* **Пары с a < 2N−1:** часть пар ещё не в памяти, но приходит во входах декодера. Такие цели можно решать «чтением»
  своих входов. Это законно (утечки нет), но это другая подзадача, и она тоже входит в L_dec.
* **RNN после DMT** оценивается только как `readout(m^rnn_t)` на позиции запроса; она прочла x_0..x_t по одному.

Новые измерения (оба режима отдельно, teacher отдельно от RNN после DMT, 3 сида) — в плане повторов
(`reruns/plan.json`, tier 1) и `EXPERIMENT_MAP_RU.md`.
