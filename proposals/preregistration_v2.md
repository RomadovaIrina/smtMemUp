# Предрегистрация версии 2 (Stack): короткое predictive-окно SMT + MemUP-supervision дальних целей

*Записано 14.10.2026 до любых обучений версии 2. Постановка согласована с научником 14.10.2026 (черновик
`proposals/smt_window_memup_draft.md`). Код: `smt_memup_window.py` (+ `smt_memup_stack.py` без изменений),
проверки `checks/test_smt_memup_window.py` (8/8). Версия 1 (полное окно, перевзвешивание) завершается и
отчитывается по своей предрегистрации отдельно.*

## Постановка
* **Задача и данные:** Stack, генератор авторов SMT, T = 64, глубина ≤ 8, 4 значения. Validation, tuning и test —
  те же наборы, что в версии 1 (те же seeds).
* **Модель:** как в версии 1 (d = 64, память 8×64, энкодер 3, декодер 2, RNN 2). Энкодер видит всё прошлое.
* **Loss:** L = L_dec^{Tf} + α·L_far + 0,1·L_dyn + 0,001·L_unif.
  * L_dec^{Tf} — авторский decoder CE по парам (anchor t, цель t + j) с j < Tf = 8, все anchors;
  * L_far — CE выбранных дальних целей (k ≥ t + 8) через тот же декодер SMT по m_t и промежуточным входам
    x_{t+1..k}. Нормировка как в версии 1: anchors с весом N_t = размер пула, внутри anchor — среднее по выбранным;
  * градиент L_far идёт в декодер и через m_t в энкодер; updater RNN учится только через L_dyn.
* **Отбор:**
  * K = 2 дальних цели на anchor;
  * детекторы — из версии 1 без переобучения: окно r = 8 и детектор по входам декодера;
  * score вычисляется под no_grad, top-K со случайным разрывом ничьих.
* **α = 1,0 для всех вариантов, без подбора.** В версии 1 подбор по одинаковой сетке выбрал α = 1,0 для каждого
  варианта; в версии 2 подбор не проводится, чтобы сэкономить ~15 обучений. Это ограничение: возможно,
  оптимальный α другой.
* **Бюджет:** SMT 3000, DMT 1500, batch 32, как в версии 1. Так версия 2 парна с ориентиром «полное окно»: тот же
  бюджет, те же начальные веса и поток данных. Seeds 7 / 17 / 27.
* **Gate (проверка работоспособности):** base_window на seed 107, tuning-набор, пороги как в версии 1:
  teacher ≥ 35%, RNN после DMT ≥ 30% на pop с давностью ≥ 8.

## Варианты (список фиксирован; в отчёт входят все)
| вариант | роль | дальние цели |
|---|---|---|
| base_window | основа | нет (α·L_far = 0) |
| uniform_far | контроль | все дальние цели |
| random_far | **основной контроль** | K случайных из пула |
| surprise_far | **проверяемый** | top-K по неожиданности для окна 8 |
| ctx_far | доп. диагностика | top-K по неожиданности при входах декодера |
| oracle_far | доп. диагностика, ORACLE | K случайных среди дальних целей с push ≤ t |
| full_window | ориентир «расширенное окно» | обучения baseline версии 1 (Tf = T), те же seeds и бюджет |

## Аудит отбора до обучения (tuning, 128 последовательностей, детекторы версии 1)
| правило | доля выбранных, которым нужна память m_t | средняя давность |
|---|---|---|
| random_far | 0,081 | 5,4 |
| surprise_far | 0,256 | 15,3 |
| ctx_far | 0,322 | 16,4 |
| oracle_far | 1,000 (пул есть у 36% anchors) | 27,0 |

## Метрики
* **Первичная:** CE RNN после DMT на test-pop с давностью ≥ 8.
* Обязательно показываются:
  * accuracy той же группы;
  * все ответы и группы давности;
  * teacher, RNN до и после DMT, голова teacher;
  * результаты каждого seed;
  * checkpoint `last`.
* **Механизм:** точность и CE на дальних парах (k ≥ t + 8) с push ≤ t, предсказанных декодером из m_t
  (`far_probe`): хранит ли промежуточная память teacher элемент. Плюс H2-удержание на фиксированном наборе ответов.

## Сравнения (variant − reference на одних test-последовательностях; best checkpoints)
* **Основное (эффект отбора):** surprise_far − random_far.
* **Эффект supervision дальних целей:** uniform_far, random_far, surprise_far минус base_window.
* **Ориентиры:** full_window − base_window; surprise_far − full_window; surprise_far − uniform_far.
* **Диагностика:** ctx_far и oracle_far минус {random_far, surprise_far}.

Для каждой разности: среднее по seeds, значение каждого seed, 95% интервал при ресэмплинге последовательностей
и интервал «seeds × последовательности» (при трёх seeds ненадёжен).

## Правило вывода
Эффект **отбора** (основное сравнение) поддержан при этом бюджете, если для surprise_far − random_far:
1. средняя ΔCE < 0;
2. ΔCE < 0 у каждого из трёх seeds;
3. 95% интервал по последовательностям не содержит 0;
4. средняя Δaccuracy ≥ 0.

Эффект **supervision дальних целей** оценивается тем же правилом для random_far − base_window.
Если правило не выполнено, эффект при этом бюджете не поддержан; приводятся размеры эффектов.

Интерпретация:
* если random_far > base_window, но surprise_far ≈ random_far — дальняя supervision полезна, а отбор при K = 2
  не добавляет;
* если far_probe растёт, а RNN нет — проблема переноса в RNN (H2), а не отбора.

## Проверка сходимости идёт параллельно
Запуски C1/C2 (`proposals/stack_convergence_check.md`) отвечают, насколько бюджет 3000/1500 далёк от сходимости.
Они не меняют этот протокол. Если окажется, что бюджет сильно недостаточен, вывод версии 2 формулируется
«при этом бюджете». Повтор на большем бюджете — отдельный предрегистрированный эксперимент: он требует
и переобучения ориентира full_window на том же бюджете.

## Test и стоимость
* Test создаётся один раз в `final_report` после всех обучений и только с разрешения пользователя. Это тот же
  набор, что в версии 1.
* Обучений: gate 1 + финал 6 × 3 = 19, около 25 мин каждое, то есть ≈ 8 ч одним процессом. С паузами из-за соседей
  по GPU — дольше.
