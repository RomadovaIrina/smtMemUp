# Черновик для обсуждения: короткое predictive-окно SMT + MemUP-supervision дальних целей

*Версия для согласования, 14.10.2026. Ничего из этого ещё не запускалось. Числа — свойства данных Stack
(генератор авторов SMT, T = 64, глубина ≤ 8, 4 значения), а не результаты обучения.*

## 0. Коротко
В первой версии (идёт финал) MemUP-подобная добавка — это **перевзвешивание** будущих целей внутри полного
predictive-окна SMT: каждая будущая цель уже обучает память m_t, а отбор меняет только веса.
Предлагаемая вторая версия ставит SMT в штатный для авторов режим **конечного окна** Tf (для длинных
последовательностей у них Tc = 256, Tf = 64). Дальние цели за окном память m_t сами по себе не обучают, и
**MemUP-слагаемое — единственный прямой сигнал от них**, ровно как в MemUP. Это ближе к исходной идее:
«если между добавлением и извлечением было много операций, MemUP может усилить обучение на событиях, которым
нужна информация из далёкого прошлого».

## 1. Что проверяет первая версия и чем отличается вторая
| | версия 1 (текущая) | версия 2 (предлагается) |
|---|---|---|
| predictive-окно SMT | полное: Tf = T | короткое: Tf = 8 |
| дальние цели (k ≥ t + Tf) в базовом loss | да, вес 1 | **нет** |
| что даёт добавка | меняет веса уже обучаемых пар | **единственная** прямая supervision дальних целей |
| вопрос | ускоряет ли акцент на неожиданных целях обучение памяти | восстанавливает ли отбор K дальних целей удержание информации, которое короткое окно иначе получает только через динамику |
| верхний ориентир | — | SMT с полным окном (финал версии 1: те же seeds, тот же бюджет) |

Версия 1 — корректная первая постановка обсуждавшейся добавки к SMT loss. Она доводится до конца и
отчитывается по своей предрегистрации. Версия 2 — отдельный эксперимент со своей предрегистрацией.

## 2. Гипотеза версии 2
При коротком окне Tf память m_t в промежуточные моменты (между push в момент s и pop в момент k > t + Tf) не обязана
хранить элемент: декодер в окне его не спрашивает. Давление на удержание приходит только через L_dyn
(m_{t+1} = f(m_t, x_{t+1}) — «амортизация кредита», раздел 3.6 статьи SMT), а это медленно. RNN имитирует
траекторию teacher, поэтому не научится нести то, чего нет в промежуточных состояниях teacher.
Это связано с H2 (перенос памяти энкодера в RNN).

**H1':** добавка α·L_far по K дальним целям, выбранным по неожиданности, улучшает итоговую RNN (после DMT) на
дальних pop по сравнению с:
* базовым SMT с коротким окном;
* random-K с тем же K;
* uniform по всем дальним целям при той же нормировке.

## 3. Формулировка

### 3.1. Loss
L = λ_dec·L_dec^{Tf} + λ_dyn·L_dyn + λ_unif·L_unif + α·L_far.

* Первые три слагаемых — авторский SMT с коэффициентами 1 / 0,1 / 0,001. Энкодер видит всё прошлое (Tc = T),
  декодер — Tf = 8 будущих целей.
* L_far = Σ_t N_t · mean_{k∈S_t} CE(y_k, q(·)) / Σ_t N_t, где:
  * пул — все дальние цели anchor t: P_t = {k ≥ t + Tf: y_k определён}, N_t = |P_t|;
  * S_t ⊆ P_t, |S_t| = min(K, N_t).
  
  Нормировка та же, что в версии 1: при random-K математическое ожидание L_far равно среднему CE по всем дальним парам.

### 3.2. Входы предиктора q — главное решение
* **P1, как в MemUP:** q(y_k | m_t, x_{k−r+1..k}) — память плюс локальное окно у цели. Это дёшево
  (K·(M + r) токенов на anchor), но в Stack ответ на pop зависит от операций между t и k: какой элемент окажется
  сверху. Даже при **идеальной** памяти без промежуточных операций можно угадать лишь ≈ 52% ответов, которым нужна
  память (оценка: самое частое значение в стеке в момент t). Задачи MemUP (Copy, T-maze) устроены иначе:
  какой элемент нужен, там определяет позиция или локальный контекст.
* **P2, рекомендуется для Stack:** тот же декодер SMT, q(y_k | m_t, x_{t+1..k}), с teacher forcing промежуточных
  входов, но loss берётся только на выбранных дальних позициях. Здесь информации достаточно (при идеальной памяти
  ответ однозначен), а дальние цели обучают память только через отбор. Это продолжение predictive-state
  объектива SMT за окно, но выборочное.

### 3.3. Градиенты (P2)
* L_far идёт в декодер (общий с L_dec) и через m_t в энкодер teacher.
* В updater RNN f градиент не попадает: f учится только через L_dyn, как в авторском SMT.
* Детекторы заморожены; score вычисляется под no_grad; top-K недифференцируем.
* DMT без изменений: teacher заморожен, readout учится на отцепленных состояниях.

### 3.4. Варианты (одинаковые K = 2, нормировка, α-сетка, бюджет, seeds, начальные веса)
| вариант | роль | отбор из P_t |
|---|---|---|
| base-window | основа | — (α = 0) |
| uniform-far | контроль | все дальние цели |
| random-K-far | основной контроль | K случайных |
| surprise-K-far | **проверяемый** | top-K по −log q(y_k \| x_{k−7..k}) (окно 8, как согласовано) |
| ctx-K-far | доп. диагностика | top-K по неожиданности при входах декодера x_{t+1..k} |
| oracle-far | доп. диагностика, ORACLE | K случайных среди целей с push ≤ t |
| full-window SMT | верхний ориентир | Tf = T (уже обучен в финале версии 1) |

## 4. Свойства данных (Stack, T = 64, Tf = 8, r = 8, K = 2)
* У 86% anchors есть дальние цели, в среднем 14 на anchor.
* Только **7%** дальних пар требуют памяти m_t (push ≤ t); хотя бы одна такая есть у 45% anchors.
* Доля «нужна память» среди выбранных:

  | отбор (идеальный, до обучения) | доля |
  |---|---|
  | random-K | 9% |
  | surprise по окну 8 | 28% (×3) |
  | surprise по входам декодера | 37% (×4) |

  При K = 2 потолок ограничен тем, сколько таких целей у anchor вообще есть.
* С P2 «неожиданные для окна» дальние цели, чей элемент положен после t, легко объясняются декодером по
  промежуточным входам. Это не Noisy-TV, а разбавление: они не учат память, но и не вредят.
* Для сравнения T = 128: дальних целей 30 на anchor, нужна память у 5%, surprise по окну даёт 26% против 7% у random-K.

## 5. Вычислительная стоимость
Стоимость декодера определяется длиной декодирования на anchor (токенов памяти M = 8 плюс горизонт):

| вариант | горизонт декодирования на anchor (T = 64) | T = 128 |
|---|---|---|
| base-window | Tf = 8 | 8 |
| full-window | в среднем 32,5 | 64,5 |
| P2, random-K / surprise-K (K = 2) | до самой дальней выбранной цели: ≈ 27 | ≈ 48 |
| P1 (как в MemUP) | K·(M + r) = 2·16, не зависит от T | то же |

* **Вывод по стоимости:** с P2 выборочная supervision почти не дешевле полного окна: каузальный декодер всё равно
  проходит промежуточные входы. Экономия MemUP по памяти и вычислениям появляется только с P1 и на длинных
  последовательностях.
* Поэтому в версии 2 на Stack мы проверяем не экономию, а **эффект отбора** при фиксированном числе supervised
  дальних целей. Вариант P1 — отдельный следующий шаг для длинных последовательностей или задач, где локальный
  контекст указывает нужный элемент.
* Энкодер (основная стоимость шага: 2048 окон по ~72 токена) одинаков во всех вариантах. Ожидаемое время одного
  обучения — как сейчас, ~20–25 мин (SMT 3000 + DMT 1500).
* Протокол как в версии 1: gate 1 + подбор α (5 вариантов × 3) + финал (6 × 3 seeds) ≈ 34 обучения ≈ 12 ч одним
  процессом или ≈ 6–7 ч двумя.
* Бюджет шагов будет уточнён по проверке сходимости (`stack_convergence_check.md`): если окажется, что нужно
  в 3–10 раз больше шагов, стоимость растёт пропорционально.

## 6. Что измеряем
* **Первичная метрика:** CE RNN после DMT на test-pop с давностью ≥ 8.
* **Отдельно:**
  * teacher;
  * RNN до и после DMT;
  * голова teacher;
  * группы давности;
  * пробник содержимого промежуточной памяти teacher: тот же декодер из m_t предсказывает дальние pop с push ≤ t;
  * H2-удержание на фиксированном наборе ответов.
* Сравнения парные по seeds; правило вывода — как в версии 1, записывается до test.

## 7. Риски
* Мало целевых пар: только у 45% anchors есть дальняя цель, которой нужна память. Отбор помогает не больше,
  чем позволяет это число; K = 2 выбран, чтобы не перекрыть пул.
* Нужен сходящийся режим (иначе разброс между seeds сопоставим с эффектами) — сначала проверка сходимости.
* Выбор Tf: при Tf = 4 дальних целей, которым нужна память, больше (9%), а эффект короткого окна сильнее; Tf = 8
  совпадает с согласованным окном детектора и порогом «дальнего» ответа.
