# Предрегистрация версии 3 (Stack): сравнение версии 1 в сходящемся режиме

*Записано 14.10.2026, до любых обучений версии 3. Код — `smt_memup_v3.py`; `smt_memup_stack.py` и
`smt_memup_window.py` не меняются. Проверки — `checks/test_smt_memup_v3.py`, 7 из 7. Каталог запуска
вычисляется `smt_memup_v3.saved_run_dir()` (хэш кода входит в identity).*

## Зачем
Версии 1 и 2 сравнивали варианты при 3000 шагах SMT (косинус LR до 0,1×) и 1500 шагах DMT. Проверка сходимости
(`outputs_convergence/README.md`) показала, что это далеко от сходимости:
* при более долгом обучении teacher с полным окном решает дальние pop на 100%;
* итоговая RNN после DMT 6000 достигает 93%;
* DMT 1500 недостаточен.

Поэтому различия вариантов в версиях 1 и 2 в основном отражали момент «включения» навыка, отсюда смена знака по
seeds. Версия 3 повторяет сравнение версии 1 в сходящемся режиме.

## Гипотезы
* **H1-ctx (подтверждающая).** Отбор будущих целей по неожиданности при входах декодера (`surprise_ctx_k`) улучшает
  итоговую RNN на дальних ответах по сравнению с baseline, random-K и uniform. В версии 1 на test это было найдено
  как дополнительная диагностика (+11 п.п. на всех seeds); здесь гипотеза проверяется заранее заявленной, на новых
  seeds и новом test.
* **H1 (согласованная форма, повтор).** surprise-K по окну 8 токенов лучше random-K и uniform.
* **H2.** Насколько итоговая RNN теряет информацию состояния teacher при собственных обновлениях; меняет ли это отбор.
* **Скорость (вторичная метрика).** Отбор может ускорять обучение памяти, даже если в пределе все варианты сходятся.
  Метрика — число шагов до 80 / 90 / 95% точности teacher на validation и до 80 / 90% у RNN в DMT.

## Что меняется относительно версии 1
| | версия 1 | версия 3 |
|---|---|---|
| SMT | 3000 шагов, косинус LR до 0,1× | **10 000 шагов, разогрев 200 шагов, затем постоянный LR 3e-4** (по умолчанию у авторов) |
| DMT | 1500 шагов, косинус | **6000 шагов, косинус** (как в проверках сходимости) |
| α | подбор по сетке, у всех выбрано 1,0 | **1,0 для всех, без подбора** |
| seeds | 7 / 17 / 27 | **37 / 47 / 57** (новые) |
| test | поток 503 | **поток 603**: новые 2048 последовательностей, не пересекаются ни с validation, ни с tuning, ни с test версии 1 (проверено) |

Остальное без изменений:
* авторский SMT loss (1 / 0,1 / 0,001), все anchors, Tc = Tf = T = 64;
* модель (d = 64, память 8×64, энкодер 3, декодер 2, RNN 2);
* генератор Stack (глубина ≤ 8, 4 значения), validation и tuning версии 1;
* детекторы версии 1 без переобучения; K = 4, окно r = 8, правила отбора, нормировка;
* выбор checkpoint по validation (SMT — CE teacher, DMT — CE RNN на дальних ответах), last как проверка устойчивости.

При расписании версии 1 код версии 3 воспроизводит обучение версии 1 бит в бит (проверка 2).

## Варианты
| вариант | роль |
|---|---|
| baseline | исходный SMT |
| uniform | контроль |
| random_k | контроль |
| surprise_k | согласованный вариант (повтор H1) |
| surprise_ctx_k | **проверяемая гипотеза H1-ctx** |
| oracle_prefix_k | ORACLE, диагностика; обучается последним, если хватит времени (решено до результатов); если обучен — входит в отчёт |

Итого 15 обучений (18 с oracle). Одно обучение при трёх параллельных процессах на свободном GPU — около 1,3 ч
(замер по версии 2). Всего около 6,5 ч (около 7,5 ч с oracle), плюс отчёт по test около 0,5 ч.

## Метрики и сравнения
* **Первичная метрика:** CE итоговой RNN (после DMT) на test-pop с давностью ≥ 8. Также точность, все группы давности,
  teacher, RNN до DMT, голова teacher, best/last, H2 (фиксированный набор и разделение по моменту push), скорость.
* **Подтверждающие сравнения (H1-ctx):** surprise_ctx_k − baseline, − random_k, − uniform.
* **Согласованные (H1):** surprise_k − random_k, − uniform.
* **Контекст:** uniform, random_k, surprise_k − baseline; surprise_ctx_k − surprise_k.
* **Диагностика (если есть oracle):** oracle − baseline, − random_k, − surprise_ctx_k.

## Правило вывода
Для каждого подтверждающего сравнения и каждого согласованного выполнены все четыре пункта:
1. средняя ΔCE < 0;
2. ΔCE < 0 у каждого из трёх seeds;
3. 95% интервал по последовательностям не содержит 0;
4. средняя Δточность ≥ 0.

* H1-ctx подтверждена, если правило выполнено для всех трёх подтверждающих сравнений.
* H1 подтверждена, если оно выполнено для обоих согласованных.

Иначе гипотеза при этом бюджете не подтверждена; приводятся размеры эффектов по seeds.
**Возможный исход:** в сходящемся режиме все варианты близки к потолку, и итоговая разница мала. Тогда главным
результатом считаются скорость и H2, а не точность в пределе.

## Порядок и разрешения
1. Обучение: `checks/run_v3.sh` (при свободном GPU; планировщик `checks/gpu_jobs.py`, одна задача на обучение, test не
   запускает). Прогресс: `python smt_memup_v3.py --phase speed` — безопасно на CPU.
2. **Test — один раз, только с разрешения пользователя:**
   `python smt_memup_v3.py --phase report --confirm-test --variants baseline,uniform,random_k,surprise_k,surprise_ctx_k[,oracle_prefix_k] --gpu-memory-fraction 0.3`,
   затем `python make_test_outputs.py --preset v3 --run <каталог> --out outputs_v3`.
3. Ничего не выбирается по test: ни вариант, ни checkpoint, ни метрика, ни формулировка.

## Чего не делаем
* Не меняем шаги, расписания, α, K, seeds, список вариантов и правило после начала обучений.
* Не прерываем и не перезапускаем обучение выборочно в зависимости от его промежуточных результатов.
* Не исключаем варианты из отчёта.
