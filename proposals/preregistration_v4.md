# Версия 4 (Stack): короткое окно SMT + дальние цели + BPTT-ориентиры — протокол

*Записано 16.10.2026, до любых обучений версии 4. Код — `smt_memup_v4.py`. `smt_memup_stack.py` и
`smt_memup_window.py` не менялись: их хэши — identity версий 1 и 2. Проверки — `checks/test_smt_memup_v4.py`.*

Протокол состоит из двух частей:
* **D — диагностика.** Зафиксирована полностью.
* **F — финальное сравнение.** Зафиксированы варианты, метрики, сравнения и правило вывода. Бюджеты шагов и LR для BPTT
  вычисляются из D по правилу, записанному здесь заранее. После D правило не меняется. Подставленные числа
  дописываются в раздел «Фиксация после D» до первого финального обучения.

## 1. Постановка (одобрена научником)
«Оставить SMT с коротким будущим окном и добавить MemUP-подобное предсказание дальних целей вне этого окна по памяти
и промежуточным входам декодера». Это loss версии 2 без изменений:

L = coef_dec·(L_dec^{Tf} + α·L_far) + coef_dyn·L_dyn + coef_unif·L_unif, коэффициенты 1 / 0,1 / 0,001.

* **L_dec^{Tf}** — авторская CE декодера по парам (anchor t, цель t + j), j < Tf, все anchors.
* **L_far** — CE выбранных дальних целей k ≥ t + Tf. Их предсказывает тот же декодер SMT по m_t и причинным
  промежуточным входам x_{t+1..k}. Короткий Tf **не обрезает** эти входы.
* **Нормировка:** anchors с весом N_t = |пул|, внутри anchor — среднее по выбранным.
* **Градиенты:** L_far идёт в декодер и через m_t в энкодер; updater RNN учится только через L_dyn.
* **Два разных окна:**
  * Tf = 8 — горизонт основного loss SMT;
  * r = 8 — локальный контекст детектора неожиданности (только `surprise_far`).
* K = 2 дальние цели на anchor, α = 1,0. Детекторы версии 1 без переобучения.
* Модель, данные, validation и tuning — как в версиях 1–3: d = 64, память 8×64, энкодер 3, декодер 2, RNN 2, Stack
  T = 64, глубина ≤ 8, 4 значения.

## 2. Варианты
| вариант | семейство | роль |
|---|---|---|
| base_window | SMT → DMT | короткое SMT без добавки (основа) |
| uniform_far | SMT → DMT | все дальние цели |
| random_far | SMT → DMT | K случайных дальних целей (контроль отбора) |
| surprise_far | SMT → DMT | top-K по неожиданности для локального окна r = 8 |
| ctx_far | SMT → DMT | top-K по неожиданности при входах декодера x_{t+1..k} без m_t |
| oracle_far | SMT → DMT | ORACLE, диагностика (см. ниже) |
| bptt_full | RNN с нуля | ориентир: глубины BPTT хватает на все зависимости (T = 64) |
| bptt_1 | RNN с нуля | ориентир: градиент только через текущее обновление |

**Oracle отличается не только отбором:**
* пул сужен разметкой генератора до дальних целей, чей элемент положен не позже t;
* поэтому меняются число выбранных целей на anchor и веса anchors N_t;
* anchors без таких целей не дают L_far вообще.

Это диагностика, а не метод.

### BPTT-ориентиры (определение)
* **Модель — та же рекуррентная модель, что итоговая SMT → DMT:** авторский класс RNN, тот же updater, состояние
  8×64, та же голова `rnn_readout`. Начальные веса совпадают с RNN SMT для того же seed.
* **Обучение:**
  * с нуля, напрямую по целевым ответам: CE на pop, маска `target_mask`;
  * без teacher, без инициализации от teacher, без DMT;
  * rollout от нулевого состояния по всей последовательности.
* **bptt_full:** градиент проходит через все 64 обновления. Loss совпадает с авторским `forward_bptt`
  (upstream `src/model.py`) — проверка 1.
* **bptt_1:**
  * состояние переносится вперёд: значения forward те же, что у full (проверка 2);
  * перед каждым обновлением входящее состояние отцепляется (`S.rnn_rollout(..., detach=True)`): loss в момент t
    учит только обновление, применённое в t, и голову;
  * состояние **не обнуляется**;
  * текущий updater получает градиент, предыдущие обновления — нет (проверки 3–4).
* **Шаг оптимизации (оба варианта):**
  zero_grad → rollout всей последовательности → masked mean CE → backward → clip 1,0 → AdamW.step → scheduler.step.
  Один optimizer.step на батч.
* **Данные:** тот же поток последовательностей, что у SMT (поток 301: шаг s — тот же батч). Те же validation, tuning,
  маски и метрики.
* **Статус:** это эмпирические ориентиры, а не математические границы качества.

## 3. Часть D — диагностика (tuning seed 107, только validation и tuning)
| запуск | бюджет (максимум) | LR |
|---|---|---|
| base_window | SMT 20 000 + DMT 12 000 | 3e-4 / 1e-4 |
| ctx_far | SMT 20 000 + DMT 12 000 | 3e-4 / 1e-4 |
| bptt_full | 20 000 | сетка 1e-4, 3e-4, 1e-3 |
| bptt_1 | 20 000 | сетка 1e-4, 3e-4, 1e-3 |

Итого 8 обучений.
* **Расписание LR — у всех разогрев 200 шагов, затем постоянный LR** (по умолчанию у авторов SMT). Так точка кривой
  означает «остановились бы здесь»; косинус привязал бы её к длине.
* **Остальное:** batch 32, AdamW (0,9; 0,95), weight decay 0,01, clip 1,0, fp32.
* **Оценка** на validation каждые 500 шагов: teacher, RNN, far-memory probe.
* **Checkpoint** — лучшая CE на дальних ответах (давность ≥ 8): SMT — teacher, DMT и BPTT — RNN.
* **Seed 107** — тот же seed, что gate версий 1–2 и проверки сходимости C1/C2. Поэтому начальные веса и поток данных
  совпадают с C1 (полное окно), и кривые сравнимы.

**Критерий достаточности бюджета** (отдельно для teacher в SMT, RNN в DMT и RNN в BPTT; метрика — лучшая на данный
момент точность на дальних ответах, validation):
* бюджет достаточен, если за последние 25% шагов прирост < 1 п.п. **или** уровень ≥ 99%;
* шаги до плато — первая оценка, где лучшая точность ≥ итоговой − 1 п.п.

**Выбор LR для BPTT** (как α в версии 1):
* для каждого варианта берётся checkpoint, выбранный по validation;
* выбирается LR с минимальной CE RNN на дальних ответах **tuning**-набора;
* при равенстве — меньший LR.

**Правило бюджета финала** (вычисляется `smt_memup_v4.py --phase diag_report`, файл `diag_decision.json`):
* SMT: 1,25 × наибольшие шаги до плато teacher среди base_window и ctx_far, округление вверх до 1000, не больше
  20 000. Один бюджет для всех SMT-вариантов.
* DMT: то же по RNN в DMT. Один бюджет для всех SMT-вариантов.
* BPTT: то же по выбранному LR, общий для bptt_full и bptt_1 — наибольший из двух.
* **Если на максимуме критерий не выполнен** — бюджет недостаточен:
  * это пишется в отчёт как ограничение;
  * увеличение бюджета — только отдельной диагностикой и по согласованию с научником;
  * молча бюджет не меняется.

**Что D не выбирает:** варианты, K, α, Tf, r, детекторы, метрики. D фиксирует только бюджеты и LR для BPTT.

## 4. Часть F — финальное сравнение
* **Seeds:** 67 / 77 / 87 (новые: 7/17/27 — версии 1–2, 37/47/57 — версия 3, 107 — tuning).
* **Test:** поток 703, 2048 последовательностей. Создаётся один раз в `final_report` и только с разрешения пользователя.
  Не пересекается с validation, tuning и test версий 1/2 (503) и 3 (603) — проверка 10.
* **Обучений:** 7 вариантов × 3 seeds = 21; с oracle — 24 (oracle обучается последним).

### Метрики и разделы отчёта (обязательно раздельно)
1. **Итоговая RNN** — первичная метрика:
   * CE на test-pop с давностью ≥ 8;
   * для SMT — RNN после DMT, для BPTT — RNN после обучения; в коде стадия `final`;
   * также точность, все группы давности, best и last checkpoint.
2. **Teacher** (только SMT): точность и CE после SMT; RNN до DMT.
3. **Far-memory probe** (только SMT): хранит ли промежуточная память teacher m_t элемент для дальних пар с push ≤ t.
   **Улучшение probe не выдаётся за улучшение итоговой RNN.**
4. **H2** (только SMT): `h2_retention.py`, фиксированный набор и разделение по моменту push.
5. **Стоимость** каждого обучения:
   * optimizer steps и число обучающих последовательностей по стадиям;
   * время обучения и оценки отдельно;
   * пиковая память allocated / reserved.
   
   Для SMT стоимость = SMT + DMT + обучение детекторов. Детекторы обучены один раз в версии 1 (2 × 2000 шагов × 32),
   их стоимость указывается как общая. Равное число шагов не означает равной стоимости.

### Сравнения (variant − reference на одних test-последовательностях; best checkpoints)
* **Дальняя supervision:** uniform_far, random_far, surprise_far, ctx_far минус base_window.
* **Отбор:**
  * surprise_far − random_far (согласованная форма);
  * ctx_far − random_far;
  * ctx_far − surprise_far.
* **BPTT-ориентиры** (описательно, без правила вывода):
  * каждый SMT-вариант − bptt_1;
  * bptt_full − каждый SMT-вариант;
  * bptt_full − bptt_1.
* **Oracle:** oracle_far − random_far, − ctx_far.

### Правило вывода (как в версиях 1–3)
Эффект поддержан при этом бюджете, если выполнены все четыре пункта:
1. средняя ΔCE < 0;
2. ΔCE < 0 у каждого из трёх seeds;
3. 95% интервал по последовательностям не содержит 0;
4. средняя Δточность ≥ 0.

Оно применяется к:
* ctx_far − base_window, ctx_far − random_far — эффект контекстного отбора;
* surprise_far − random_far — согласованная форма H1;
* random_far − base_window — эффект дальней supervision.

**Интерпретация с BPTT:**
* bptt_1 заметно ниже bptt_full — задача требует переноса кредита через много шагов;
* SMT-вариант выше bptt_1 — SMT частично решает перенос без BPTT;
* разрыв до bptt_full — сколько остаётся.

## 5. Чего не делаем
* Не меняем после D: варианты, K, α, Tf, r, детекторы, метрики, правило вывода и правило бюджета.
* Не подменяем detach обнулением состояния; не обрезаем BPTT ради памяти: при нехватке — microbatch и накопление
  градиента с корректной нормировкой. По benchmark память не ограничивает.
* Не выбираем ничего по test. Не исключаем варианты из отчёта.
* Не запускаем версию 3: это полное окно, а не целевая постановка. Её код и протокол сохраняются как есть.
