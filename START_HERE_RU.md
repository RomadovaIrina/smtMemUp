# С чего начать: SMT × MemUP на Stack и MQAR

> **Два окна не путать.**
> * **Stack версии 1** (архив, единственный test): **полное окно Tf = T = 64**. Декодер предсказывает все будущие
>   ответы последовательности.
> * **Целевая постановка** (версии 2, 4, абляции, этот путь): **короткое окно Tf = 8** плюс, по желанию, дальние цели
>   (`ctx_far`).
> * **Окно энкодера в обоих случаях — весь префикс x_0..x_t.** Меняется только то, какие выходы декодера входят в loss.

## 2. Одна команда: маленький пример на CPU (~2 минуты)

```bash
python smt_minimal.py demo --task stack
```

Что делает команда:
1. Обучает крошечную модель на Stack (T = 16): SMT 150 шагов, затем DMT 100 шагов.
2. Печатает одну последовательность: позиция, смысл, токен, вход, метка, маска.
3. Берёт последний pop этой последовательности и показывает:
   * окно энкодера для якоря t;
   * CE выхода j = 0 в SMT-loss и по какой маске он входит в `L_dec^Tf`;
   * тот же ответ как выход j = 1, 2, 3 более ранних якорей;
   * строки оценки teacher и RNN: предсказание, метка, верно / неверно, CE.

То же для одного MQAR-запроса (T = 16, N = 2), вместе с двумя режимами «память до запроса»:
```bash
python smt_minimal.py demo --task mqar
```

Числа демо не являются результатами: модель крошечная и почти не обучена.

## 3. Порядок чтения

1. **`smt_minimal.py`** — весь путь в одном файле, сверху вниз:
   * 1 — данные (стр. 175–229);
   * 2 — окна SMT (236–249);
   * 3 — модели (256–314);
   * 4 — прямые проходы (321–351);
   * 5 — лоссы (358–454);
   * 6 — шаг оптимизатора (461–472);
   * 7 — оценка (480–537);
   * 8 — запуски (543–700).
2. **`CODE_WALKTHROUGH_RU.md`** — тот же файл по блокам строк: входы, формы тензоров, выходы, формулы лоссов рядом с
   кодом, куда идёт градиент, что значат `detach`, teacher, m_t, m̂_t, Tf, K, якорь, маски.
3. **`EXAMPLES_RU.md`** — настоящие последовательности Stack (T = 64) и MQAR (T = 16 / 32) по позициям; окна для одного
   длинного pop; два режима чтения памяти в MQAR и проверка отсутствия утечки.
4. **`MODELS_RU.md`** — схемы всех обученных моделей с размерами. Отдельно показано, что обновитель SMT — не GRU и не
   детектор.
5. **`EXPERIMENT_MAP_RU.md`** — каждое число → конфиг → команда → файлы → метрика → сиды → test / validation.
6. **`AUDIT_RU.md`** — что завершено, что подтверждается данными, что устарело, ограничения. В том числе разбор
   абляции `detached`.
7. **Авторские классы** — `upstream/smt/src/model.py`: `Teacher` 105–167, `RNN` 184–226, лоссы 21–59.

Архивные `smt_memup_*.py` читать не обязательно: `smt_minimal.py` воспроизводит их поведение, и это проверено.

## 5. Повторы на GPU (по согласованию)
