## 3. Абляция `detached`: градиент L_dyn в энкодер НЕ отключён

**Код:**
* `checks/smt_memup_ablation.py:51-57` подменяет `calc_mse_loss(pred, target)` на `calc_mse_loss(pred, target.detach())`;
* в `smt_memup_window.py:131-133` цель — состояние энкодера `m_t`, а вход обновителя `prev` — тоже состояние
  энкодера `m_{t-1}`, и он **не** отцеплен:
  ```
  prev = cat([0, memory[:, :-1]])                       # m_{t-1} — выход энкодера, с градиентом
  pred = rnn.rnn_update(prev, x_t)
  dyn  = calc_mse_loss(pred, memory)                    # абляция: memory.detach()
  ```

**Проверка на практике** (`python checks/check_detached_gradients.py`): настоящий `smt_window_loss`,
`coef_dec = coef_unif = 0`, то есть loss = L_dyn; Stack T = 16, 4 последовательности.

| режим | норма градиента L_dyn на параметрах энкодера | норма градиента на обновителе |
|---|---|---|
| совместный (как `full`) | 0,352 | 0,521 |
| абляция `detached` (как в архиве) | **0,566** (все 33 тензора энкодера получают градиент) | 0,521 |
| авторский `detach_rnn=True` (`upstream/smt/src/model.py:322-323`: отцеплены и вход, и цель) | **0** | 0,521 |

**Вывод.**
* Архивная абляция `detached` убирает только путь градиента через цель `m_t`.
* Путь через вход обновителя `m_{t-1}` остаётся: L_dyn по-прежнему сдвигает энкодер, причём градиент даже больше по
  норме.
* Это **не** «detached SMT» статьи SMT (разд. 3.6). Описание в `checks/smt_memup_ablation.py`,
  `outputs_ablation/README.md` и `proposals/answer_2026-10-19.md` исправлено, имя эксперимента сохранено.
* Правильное название: «L_dyn без градиента через цель (target-detached)».

**Ещё о записи эксперимента:**
* identity у `detached` и `full` одинаковый (`runs/stackv4_8318239d86e6`): патч в identity не записан, прогоны
  различаются только каталогом;
* настоящий вариант авторской семантики добавлен как **новый** опыт: `dyn_detach="both"` в `smt_minimal.py`,
  тест `checks/test_minimal_equivalence.py::test_dyn_detach_modes`.

## 6. Честные ограничения (сводка)

1. **Почти все результаты после v1 — один сид (107) и validation / tuning.** Единственный test — v1 (полное окно,
   3 сида), и он не про целевую постановку.
2. **Короткое окно Tf = 8 — целевая постановка, но финал F (3 сида, test) не проводился.**
3. **Абляции не независимы:**
   * `full` — продолжение той же траектории, что диагностика;
   * `tf64` совпадает с «полным окном» v4;
   * `detached` не отключает градиент L_dyn в энкодер (раздел 3).
4. **«RNN до DMT»** — нестабильная величина (±20 п.п. между соседними оценками).
5. **MQAR:**
   * доступ teacher к ответу измерялся только в режиме j = 0, когда энкодер уже видел ключ запроса;
   * режим «память до запроса» не измерялся; добавлен в `smt_minimal.py` и в план повторов;
   * тест узкого места — один сид, только логи, причина не изолирована.
6. **Равное число шагов ≠ равная стоимость:** DMT и BPTT — последовательные откаты по T шагам, SMT — параллельный
   шаг; время сохранено в `cost.json` / `summary.json`.
7. **Checkpoints большинства опытов в git нет:** пробы и H2 по ним не воспроизводятся из репозитория.
