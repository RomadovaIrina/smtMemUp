# Предрегистрация сравнения H1 (зафиксировано 13.10.2026, до подбора alpha и до создания test)

Запуск: `runs/stack02_4c69a2819ab8`, код `smt_memup_stack.py` sha256 f0552c46…;
Stack T=64, глубина 8, 4 значения; SMT 3000 шагов, DMT 1500, batch 32, все anchors; K=4; alpha ∈ {0.1, 0.3, 1.0}.

## Почему этот бюджет
Гипотеза сформулирована для ограниченной памяти и **ограниченного бюджета обучения**. Baseline прошёл gate,
но на дальних pop далёк от потолка (tuning: teacher 38%, RNN после DMT 41%, случайный уровень 25%),
поэтому есть пространство для эффекта. Тривиальный эффект «больше шаг на трудных целях» контролирует
uniform с подобранным alpha, эффект «любой добавочный шумный loss» — random-K.

## Варианты (список фиксирован, после test не меняется)
| вариант | роль |
|---|---|
| baseline | контекст |
| uniform, random_k | основные контроли |
| surprise_k (окно r=8) | **проверяемый согласованный метод** |
| surprise_ctx_k (score по входам декодера x_{t+1..k}, без памяти) | вторичный: проверка «учёта источника до/после anchor» без metadata |
| oracle_prefix_k (metadata: push ≤ t) | диагностический ORACLE, не алгоритм |

## Первичная метрика и сравнения
CE RNN после DMT на test-pop с delay ≥ 8 (в Stack это delay ≥ 9), checkpoint по validation.
Сравнения: surprise_k − random_k и surprise_k − uniform.

**H1 поддержана**, если в обоих сравнениях разность CE < 0 у всех трёх seeds и accuracy на той же группе
в среднем не хуже. При трёх seeds одинаковый знак случайно получается с вероятностью 1/8 на сравнение
(односторонне), поэтому это предварительное свидетельство: при поддержке тот же протокол повторяется на
двух дополнительных seeds до итогового вывода. Иначе H1 не поддержана при этом бюджете.

## Интерпретация с oracle (тот же критерий знаков)
| oracle лучше контролей | surprise_k лучше | вывод |
|---|---|---|
| нет | — | на Stack в этом режиме усиление memory-dependent целей само по себе не помогает; вывод не зависит от detector |
| да | нет | механизм полезен, узкое место — score; surprise_ctx_k показывает, исправляет ли его учёт anchor |
| да | да | H1 поддержана; разница oracle − surprise_k показывает запас отбора |

Если teacher улучшается, а RNN нет, это проблема переноса в updater (H2), а не опровержение отбора.

## Вторичное (не заменяет первичное)
teacher; RNN до DMT; голова teacher на состоянии RNN (shared); delay ≥ 16; checkpoint `last`; MSE памяти.

## Чего не делаем
Не меняем конфиг, alpha, K или список вариантов после создания test; не выбираем постфактум лучший score;
surprise_ctx_k и oracle не выдаём за согласованный метод.
